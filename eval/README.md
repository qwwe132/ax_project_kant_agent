# 평가셋 작성 안내

질문, 정답, 근거 원문을 기록하는 JSON 파일의 공통 형식과 채점 기준입니다.

| 파일 | 구성 |
| --- | --- |
| `dev.json` | 10문항. 단순 사실 확인 8문항, 문서 외 함정 질문 2문항 |
| `test.json` | 20문항. 단순 사실 확인 10문항, 복합 추론 질문 7문항, 문서 외 함정 질문 3문항 |
| `sample.json`, `cache.json` | 이전 형식(`id`, `type`, `expected_answer`, `allowed_evidence`)을 유지합니다. 평가 코드는 두 형식을 모두 읽습니다. [팀 공용 샘플 사용법](../README.md#팀-공용-샘플-데이터)을 참고하세요. |

## 문항 필드

```json
{
    "query_type": "단순 사실 확인",
    "question": "사용자가 입력할 질문",
    "answer": "정답 문장",
    "context": "정답 근거 원문"
}
```

| 필드 | 작성 내용 |
| --- | --- |
| `query_type` | 단순 사실 확인, 복합 추론 질문, 문서 외 함정 질문 중 하나 |
| `question` | 사용자가 입력할 질문 |
| `answer` | 답변에 들어가야 할 핵심 사실을 담은 정답 문장. 문서 외 함정 질문은 정보 부족 안내 |
| `context` | 정답 근거 원문. 문서 외 함정 질문은 관련은 있지만 답은 없는 원문(함정 문서) |

- 문항 ID는 파일 안 순서로 붙습니다(`dev.json` → DEV-001~, `test.json` → TEST-001~). 실행 결과의 `question_id`와 연결되므로 **문항 순서를 바꾸지 않습니다.** 문항을 추가할 때는 끝에 붙입니다.
- `context`는 `data/processed/chunks.json`의 청크 본문을 그대로 옮겼습니다. 근거가 여러 청크에 걸치면 빈 줄로 이어 붙였습니다.
- 문서 외 함정 질문의 `context` 출처: DEV-009 `NOTION-018-001`(회의실 예약 방법), DEV-010 `NOTION-014-022`(공가 승인 소요 기간), TEST-018 `NOTION-010-011`(럭키드로우 진행 방식), TEST-019 `NOTION-012-002`(건물 주소), TEST-020 `NOTION-002-003`(강의실 수칙)·`NOTION-018-002`(회의실 식사 금지)

## 고정 및 채점

- 2026-11-23 수집 Notion 원문 및 KANT AX 시간표 기준 초안입니다. 문서 ID는 [출처 목록](../data/sources.md)과 연결됩니다.
- 근거는 `data/processed/chunks.json`(394청크, 커밋 `40d4073`, PR #17 청킹 기준)의 청크 중, 청크 하나만으로 정답 사실을 뒷받침하는 것만 넣었습니다. 같은 사실이 여러 문서에 있으면(예: 부정출결 내용이 NOTION-013·015·016에 모두 있음) 모두 넣었고, 키워드만 겹치고 정답 사실이 없는 청크와 질문의 핵심 판단 기준 없이 보충 조건만 담은 청크(예: TEST-015에서 09:10 지각 기준이 없는 NOTION-013-004)는 넣지 않았습니다.
- Hit@5는 검색 상위 5개 청크 중 본문이 `context` 안에 그대로 들어 있는 청크가 하나라도 있으면 1점입니다(공백 차이는 무시). Recall@5는 `context` 글자 수 중 상위 5개의 근거 청크가 덮는 비율입니다.
- 청킹·원문이 바뀌면 청크 본문이 달라질 수 있으므로 `context`를 다시 확인하고, 최종 실행 전에 문서·청크·평가셋 버전을 고정합니다.
- 개발셋으로 튜닝하고 최종 평가셋을 실행 전에 고정합니다. 평가 정답표는 검색 색인과 답변 프롬프트에서 제외합니다.
- 단순 사실 확인·복합 추론 질문 17문항은 Hit@5, 정답 충족, 근거 적합을 각각 0/1로 채점합니다.
- 문서 외 함정 질문 3문항은 정보 부족 안내를 0/1로 채점합니다. 호출 오류는 0점입니다.
