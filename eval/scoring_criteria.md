## 1. 지표별 채점 기준 (Ragas 4지표)

모든 지표는 Ragas(LLM 채점)로 문항마다 0~1 사이 점수를 매기고, 구성(A/B/C)별 평균과 표본 수(n)로 보고합니다.

| 지표 | 분류 | 묻는 질문 | 채점 대상 | 계산 방식 |
| --- | --- | --- | --- | --- |
| Context Precision (CP) | 검색 | 정답에 쓸모 있는 자료가 **위쪽 순위**에 있나? | 답변 가능 문항 (답변 상태와 무관) | 자료마다 쓸모 있음(1)/없음(0) 판정 → 평균 정밀도 |
| Context Recall (CR) | 검색 | 정답을 이루는 정보가 가져온 자료에 **빠짐없이** 있나? | 답변 가능 문항 (답변 상태와 무관) | 정답 문장을 단위 문장으로 쪼갬 → 자료로 뒷받침되는 비율 |
| Faithfulness (F) | 생성 | 답변의 주장이 **가져온 자료에만** 근거하나? | 정상 답변(`ok`) 문항 | 답변을 단위 주장으로 쪼갬 → 자료로 뒷받침되는 비율 |
| Answer Relevancy (AR) | 생성 | 답변이 **질문 의도에** 맞나? | 정상 답변(`ok`) 문항 | 답변에서 질문을 역생성 → 원래 질문과의 유사도 |

- 검색 결과가 없으면 CP, CR은 LLM 호출 없이 0점입니다.
- 근거 없는 문항(정보 부족 안내 대상)은 Ragas로 채점하지 않고, 답변이 단정하지 않고 정보 부족을 안내했는지 사람이 직접 확인합니다.
- 실행: `ragas_eval.py` → `<run_id>_ragas.csv` (LLM 점수는 덮어쓰지 않음)

### 1-1. 실패 원인 진단 (`failure_analyzer.py`)

문항별 점수가 임계치 미만이면 아래와 같이 진단합니다. 검색 진단은 하나만, 답변 진단은 여러 개가 동시에 붙을 수 있습니다.

| 진단 | 조건 | 담당 | 처방 |
| --- | --- | --- | --- |
| RETRIEVAL_FAILURE | CR < 임계치 | 검색 | 하이브리드·BM25·청킹 점검 |
| RANKING_ISSUE | CR ≥ 임계치, CP < 임계치 | 검색 | 리랭크·후보 수 점검 |
| MISSED_ANSWER | 검색 정상인데 답변이 `no_evidence` | 답변 | 답변 조건 점검 |
| GENERATION_FAILURE | F < 임계치 | 답변 | "문맥만 사용" 규칙 강화 |
| OFF_TOPIC | AR < 임계치 | 답변 | 프롬프트 점검 |
| CALL_ERROR / JUDGE_ERROR | 호출 오류 / Ragas 채점 실패 | 평가 | 오류 확인 후 재실행 |
| NOT_SCORED | 근거 없는 문항 | 평가 | 정보 부족 안내 직접 확인 |

### 1-2. 회귀 검증 (`compare.py`)

- Baseline(A · 벡터) 대비 Improved(C · 하이브리드 + 리랭크)를 비교합니다.
- **통과 조건: CP와 CR의 평균이 둘 다 상승** (`regression_passed: true`)
- 양쪽 모두 점수가 있는 문항끼리만 평균을 냅니다.
- F, AR이 하락하면 통과 여부와 별도로 기록합니다.
- 평균이 올라도 CP 또는 CR이 하락한 문항은 실패 분석에 기록합니다.

### 1-3. 참고 지표 (기존 코드 유지)

비용이 들지 않아 함께 출력하지만, 판단 기준으로 쓰지 않습니다.

| 지표 | 계산 | 주의 |
| --- | --- | --- |
| Hit@5, Precision@5, Recall@5 | `score.py`. 허용 근거와 검색 후보의 `chunk_id`(없으면 `document_id` + `source_location`) 비교 | 평가셋의 `source_location`이 청킹 결과와 글자가 달라 `chunk_id` 매핑 전에는 0으로 나옴. Precision@5는 근거가 1개인 문항에서 최대 0.2 |

- LLM 채점: Ragas 0.4.4, 채점 모델 `gpt-6-luna`, 임베딩 `text-embedding-3-small`. 실행마다 결과 파일에 모델·버전이 함께 기록됨
- 사람 검토자: <이름> (LLM 진단 결과를 표본 검토하고, 근거 없는 문항을 직접 확인)
- 의견이 다를 때 처리: <팀 합의 후 작성>
- LLM 점수와 사람 검토 결과는 구분해서 기록
- 진단 근거(`advice`)는 문항마다 한 줄로 남김

## 5. 지켜야 할 규칙

- 최종 평가 20문항은 튜닝에 쓰지 않는다.
- 최종 결과를 보고 질문을 바꾸거나 기준을 낮추지 않는다.
- 임계치는 개발셋 결과로만 조정하고, 최종 평가 전에 확정한다.
- 실패, 오류, 재시도 기록을 삭제하지 않는다.
- 최종 평가 후 추가 실험은 본 평가와 분리해서 기록한다.
- 실제 문서로 Ragas를 실행하기 전에 외부 모델 전송 가능 여부를 확인한다(`data/sources.md`).
