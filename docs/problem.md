
# KANT AGENT
## RAG 기반 부트캠프 교육과정 안내 Knowledge Agent

## 1. 프로젝트 개요

### 1.1 프로젝트명
KANT AGENT

### 1.2 프로젝트 소개
KANT AGENT는 부트캠프 교육생을 대상으로
교육기관의 출결 규정, 교육 일정, 프로젝트 일정,
훈련장려금 및 교육과정 운영 규칙에 대한 질문에
답변하는 RAG 기반 Knowledge Agent이다.

교육기관에서 제공하는 공식 문서를 지식 베이스로
구축하고, 교육생의 자연어 질문에 대해 관련 문서를
검색하여 근거 기반 답변을 제공한다.

### 1.3 목표 사용자
- 부트캠프 교육생
- 신규 입과 예정자
- 교육과정 운영 담당자

## 2. 문제 정의

### 2.1 현재 문제점
- 출결 규정과 교육 일정 등이 여러 공지 및 문서에 분산되어 있다.
- 교육생이 필요한 정보를 찾기 위해 공지사항을 직접 검색해야 한다.
- 동일한 질문이 교육 운영 담당자에게 반복적으로 전달될 수 있다.
- 교육생은 공지·시간표·규정을 찾아 적용 시점과 예외 조건을 대조하고, 모호하면 운영 담당자에게 문의한다.
- 오답이나 근거 누락은 출결 처리, 제출 기한, 훈련장려금 조건을 잘못 이해하게 할 수 있다.
- 교육과정 운영 규칙을 잘못 이해할 가능성이 있다.
- 변경된 일정이나 규정을 확인하기 어려울 수 있다.

### 2.2 해결 방안
- 교육기관의 공식 문서를 통합하여 검색 가능한 지식 베이스 구축
- 자연어 기반 질의응답 제공
- 질문과 관련된 문서를 검색하여 정확한 정보 제공
- 답변에 근거 문서 및 관련 조항 표시
- 문서에서 확인할 수 없는 내용은 답변 제한
- 문서의 기준일과 변경 이력을 고려한 답변 제공

### 2.3 기대 효과
- 교육생의 정보 탐색 시간 단축
- 교육 운영 담당자의 반복 문의 감소
- 교육 규정 및 일정에 대한 접근성 향상
- 근거 기반 답변을 통한 정보 신뢰성 확보

## 3. 프로젝트 범위

### 3.1 구현 범위 (In Scope)

#### 출결 관련 질의응답
- 출석 인정 기준
- 지각 및 조퇴 처리 기준
- 결석 처리 기준
- 출석률 계산 기준
- 공결 및 증빙서류 안내

#### 교육 일정 관련 질의응답
- 교육과정 전체 일정
- 일별 수업 시간표
- 교육과정별 학습 일정
- 휴강 및 휴일 일정

#### 프로젝트 관련 질의응답
- 프로젝트 진행 기간
- 프로젝트별 주요 일정
- 중간 및 최종 발표 일정
- 프로젝트 제출 기준

#### 교육 운영 관련 질의응답
- 훈련장려금 관련 규정
- 교육생 준수 사항
- 교육기관 공지사항

#### RAG 핵심 기능
- 문서 수집 및 파싱
- 문서 청킹 및 임베딩
- A는 Vector 검색, B는 동일 청크의 BM25와 Vector를 결합한 Hybrid 검색, C는 B 후보를 별도 reranker로 재정렬하는 구성으로 비교한다.
- 캐싱 또는 쿼리 리라이트 중 한 가지를 구현하고 별도로 검증한다.
- 질문·답변·근거·오류를 확인할 실행 인터페이스 한 가지를 제공한다.
- 근거 기반 답변 생성
- 답변 출처 표시
- 검색 성능 평가

### 3.2 제외 범위 (Out of Scope)
- 실제 출결 등록 및 수정
- 개인별 출결 데이터 실시간 조회
- 훈련장려금 실제 지급 내역 조회
- 교육 일정 자동 변경
- 교육기관 관리자 업무 자동 처리
- 공식 문서에 없는 규정의 임의 판단
- 외부 시스템에 쓰기, 실제 결제·발송, 모델 학습·파인튜닝

## 4. 문서 범위 및 준비

### 4.1 수집 대상 문서

| 문서 ID | 문서명 | 주요 내용 | 상태 |
|---|---|---|---|
| DOC-001 | 출결 관리 규정 | 출석, 지각, 조퇴, 결석 | 수집 예정 |
| DOC-002 | 교육과정 운영 안내 | 교육생 준수 사항 | 수집 예정 |
| DOC-003 | 교육 시간표 | 수업 시간 및 과목 일정 | 수집 예정 |
| DOC-004 | 프로젝트 일정표 | 프로젝트 진행 및 발표 일정 | 수집 예정 |
| DOC-005 | 훈련장려금 안내 | 지급 조건 및 관련 규정 | 수집 예정 |
| DOC-006 | 교육기관 공지사항 | 휴강, 일정 변경 등 | 수집 예정 |

### 4.2 지원 문서 형식
- PDF
- Markdown
- TXT
- Excel (XLSX)
- CSV

### 4.3 문서 관리 기준
- 교육기관에서 제공한 공식 자료 우선 사용
- 문서별 고유 ID 부여
- 공개 공식 자료를 우선하고, 필요한 경우 가상 문서를 가상 자료로 표시하여 사용한다.
- 목록에 문서 ID, 제목, 출처, 이용 조건과 외부 모델 전송 가능 여부, 버전 또는 수집일, 원문 위치를 기록한다.
- 답변 가능한 서로 다른 질문 25개를 뒷받침하고, 유사 용어 또는 예외 조건을 혼동할 수 있는 문서를 최소 2개 포함한다.
- 모든 청크에 안정적인 청크 ID, 문서 ID, 페이지·절·행 등 원문 위치를 연결한다.
- 최신 공지와 기존 규정의 관계 확인
- 문서 변경 시 재색인 가능하도록 설계
- 개인정보 및 접근 권한이 없는 자료 제외

## 5. 질의응답 범위

### 5.1 출결 관련 질문 예시
- 지각은 몇 시부터 처리되나요?
- 조퇴하면 출석 시간은 어떻게 계산되나요?
- 병원 진료를 받으면 공결 처리가 가능한가요?
- 결석 시 제출해야 하는 서류는 무엇인가요?
- 출석률 기준은 어떻게 되나요?

### 5.2 교육 일정 관련 질문 예시
- 오늘 수업은 무엇인가요?
- 다음 주 교육 일정은 어떻게 되나요?
- 이번 교육과정은 언제 종료되나요?
- 점심시간은 언제인가요?

### 5.3 프로젝트 관련 질문 예시
- 현재 프로젝트 제출 마감일은 언제인가요?
- 프로젝트 발표 일정은 언제인가요?
- 프로젝트 평가 기준은 무엇인가요?
- 다음 프로젝트는 언제 시작하나요?

### 5.4 훈련장려금 관련 질문 예시
- 훈련장려금 지급 조건은 무엇인가요?
- 결석하면 훈련장려금에 영향이 있나요?
- 출석률이 지급 기준에 미달하면 어떻게 되나요?

### 5.5 답변 제한 기준
- 공식 문서에 없는 정보는 임의로 생성하지 않는다.
- 근거가 부족하면 확인할 수 없다고 안내한다.
- 일정 질문은 기준 날짜를 고려한다.
- 상충하는 문서가 발견되면 차이를 안내한다.
- 규정의 최종 해석이 필요한 경우 운영 담당자 확인을 안내한다.

## 6. 성공 기준

품질·지연·비용의 우선순위와 팀 목표는 최종 실험 전에 합의해 확정한다. 아래 품질 목표는 기존 초안을 반영한다.

| 평가 항목 | 팀 목표 초안 | 평가 방법 |
|---|---|---|
| 검색 Hit@5 | 0.80 이상 | 허용 근거가 상위 5개에 하나라도 있으면 1. 검색 실패는 0. 합계/17 |
| 정답 충족 | 90% 이상 | 필수 핵심 사실을 모두 충족하고 모순이 없으면 1. 합계/17 |
| 근거 적합 | 100% | 실제 검색 결과를 인용하고 주요 주장을 뒷받침하면 1. 합계/17 |
| 정보 부족 안내 | 90% 이상 | 무근거 단정 없이 안내하면 1. 호출 오류는 0. 합계/3 |

동일한 생성 모델·프롬프트·출력 한도로 A/B/C 각 20문항을 1회씩 실행한다. 60건의 원본 기록과 함께 검색·생성 성공 수/시도 수, 성공 응답의 전체 지연 평균·중앙값과 표본 수, 오류·타임아웃 수를 보고한다. 캐싱은 A/B/C 비교에서 비활성화하고 별도 15건으로 검증한다. 리라이트를 선택하면 C+리라이트 20건을 추가하고 C와 비교한다.

## 7. 평가 데이터셋

### 7.1 평가 목적
KANT AGENT가 교육기관의 공식 문서에서
질문과 관련된 정보를 정확하게 검색하고
문서에 근거한 답변을 생성하는지 검증한다.

### 7.2 평가 질문 유형
- 단순 사실 검색
- 규정 및 조건 검색
- 날짜 및 일정 검색
- 여러 규정을 종합하는 질문
- 문서에 정답이 없는 질문
- 상충하거나 오래된 문서 관련 질문

### 7.3 평가 데이터 예시

※ 실제 정답은 공식 문서 수집 후 작성한다.

| ID | 질문 | 기대 정답 | 근거 문서 | 유형 |
|---|---|---|---|---|
| Q001 | 지각 기준은? | 문서 확인 후 작성 | DOC-001 | 규정 검색 |
| Q002 | 공결 증빙서류는? | 문서 확인 후 작성 | DOC-001 | 조건 검색 |
| Q003 | 점심시간은? | 문서 확인 후 작성 | DOC-003 | 사실 검색 |
| Q004 | 프로젝트 마감일은? | 문서 확인 후 작성 | DOC-004 | 일정 검색 |
| Q005 | 결석 시 장려금은? | 문서 확인 후 작성 | DOC-005 | 조건 검색 |
| Q006 | 내 현재 출석률은? | 개인 데이터가 없으면 확인 불가 | 없음 | 답변 불가 |

### 7.4 평가 데이터셋 분리
- 전체 평가 질문 목표: 30개
- 개발셋(`eval/dev.json`): 답변 가능 8개, 근거 없음 2개
- 최종 평가셋(`eval/test.json`): 직접 검색 10개, 표현 변형·유사 조건 구분 7개, 근거 없음 3개

#### 개발셋
- 검색 방식 개선
- 청킹 전략 비교
- 프롬프트 개선
- 오류 분석

#### 테스트셋
- 최종 검색 및 답변 성능 평가
- 개발 중 튜닝에 사용하지 않음

#### 분리 기준
- 답변 가능 문항에 ID, 유형, 질문, 기대 답변의 핵심 사실, 허용 근거 문서·청크와 원문 위치를 기록한다.
- 근거 없음 문항의 기대 답변은 정보 부족 안내로 두고 근거 ID를 비우며 부재 판정 이유를 기록한다.
- 동일 사실에 대한 유사 질문 중복 방지
- 평가 정답표는 검색 색인과 답변 프롬프트에서 제외한다. 문서·청크·평가셋 버전은 최종 평가 전에 고정한다.
- 테스트셋은 최종 평가 전까지 고정
